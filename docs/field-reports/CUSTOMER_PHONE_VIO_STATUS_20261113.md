日期：2026-11-13（香港时间）。本轮证据位于本机 `customer-session-14/`，不提交手机截图、录制数据或设备凭据。

## 结论与版本

InsightCapture `b35c2e1` 已部署到 Jetson。手机通过电脑 USB 调试直接截图和操作；实际页面及 WebRTC 仍走手机到 Jetson 的热点链路。本轮修复定位失败原因不明、故障提示挤压预览的问题。头部相机仍报告 `NOT_INITED`，因此不能宣布完整采集验收通过。

未合并 main、推送或制作客户安装包。InsightCapture 仍拥有自身代码和资源，没有新增对 ego_dashboard 或 LooperHub 的运行、构建、升级依赖，也没有共享源目录或自动同步关系。本轮不修改相机固件。

## 改动

- `runtime/ros/node.py` 在已有 PoseBridgeNode 内按 namespace 去重订阅 `/<namespace>/camera/vio_status`，使用兼容相机发布者的 BEST_EFFORT、深度 1 QoS；单调时钟记录收到时间。回放不覆盖现场诊断。
- `runtime/camera_health.py` 在现有锁内快照，输出 `vio_status`、`vio_status_age_sec`、`vio_status_fresh`。沿用已有 stale 窗口；过期状态不作为当前原因。真实图像 / VIO 数据仍决定就绪，没有增加状态话题录制门槛。
- 手机页面区分初始化、恢复、停止、跟踪丢失、输入中断、缺少内部标定；上游 USB / NTP / 启动 / 图像异常优先，未知或过期状态不猜原因。
- 内部相机标定缺失的建议与页面公共地图“重新校准”明确区分。
- 采集页压缩故障摘要，完整预检失败与警告保留到设备页。状态按钮保留至少 44 CSS 像素触摸高度，预览按可用空间计算，避免固定操作栏覆盖。
- 修改均有自有前端构建产物；不依赖地图进程提供故障原因。

## 真实 Android 验证

OnePlus 7T Pro / Android 11 / Chrome 132，使用本机 ADB 服务端口 5039，读取真实 Chrome 标签页及屏幕。手机到 `10.77.0.1` 的路由为 wlan0、源地址 `10.77.0.106`，没有 ADB reverse 映射。实际媒体为 `10.77.0.106:40937 -> 10.77.0.1:8768/UDP`。

同一 384 × 703 CSS 视口中，总览视频边长从 176.39 增至 203.65 像素，底部完整位于固定栏上方。真实头部状态显示“定位尚未初始化”；点击状态入口后可见检查建议、完整预检错误和存储警告。通过实际触摸切换英文、返回采集，再恢复简体中文。离开采集页释放预览，返回后重新播放。

英文采集页同一 SSRC 的 37.248 秒窗口新增解码 1,118 帧，平均 30.015 fps，RTP 丢包和冻结均无增量；浏览器呈现掉帧增加 3。总览解码尺寸为 1280 × 1280。这个窗口不替代长时间稳定性测试。

另观察到一次设备页显示“2 个必要录制话题无发布者”。后续 72.344 秒、31 次状态采样未复现；不能据此认定已解决或定位根因。该观察列入后续话题发现复查。
