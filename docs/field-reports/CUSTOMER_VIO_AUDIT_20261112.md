## 检查器边界缺陷与修复

回归数据复现：全零源时间戳和无法解析的消息头，旧深度检查均可返回通过。原实现还在排序后丢失倒退信息，并把“低于标称频率的数量差”表述为丢失。

修复后：

1. 无效/未设置源时间戳不再替换为录制机时间；缺少两个不同有效源时间戳不能判为通过。
2. 报告有效、不同、重复、倒退及无效源时间戳计数。重复和倒退作为诊断，不额外阻止采集；频率计数仍包含重复消息，报告明确说明这一限制。
3. API / Qt 默认单遍检查 MCAP 源时间戳；`--fast` 仍可用，但明确不检查源时间戳健康。
4. CLI / Qt 使用“频率缺额”和“检查通过/需复检”，明确源端、传输和写盘归因尚需配对证据。

没有调整标称频率、0.5% 缺额阈值、NTP 约束或开始录制门槛。源端 VIO 行为没有通过固件改动掩盖。当前 LooperHub 源码不等于相机已部署二进制，本轮未刷写相机，也未修改 Ego 工程。

7 项新增针对性回归与既有测试合计 160 项通过；真实 MCAP 扫描结果与三方比对一致。完整代码、部署及 Qt 构建身份以本轮最终交付记录为准。
