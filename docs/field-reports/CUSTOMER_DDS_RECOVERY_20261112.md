# 客户走查 06：空图像消息的分层定位

日期：2026-11-12。现场基线 `5c6db61`（功能 `2602698`）。本轮针对上一轮
断连恢复后 MCAP 中的空 Image，先定位首次出现的层次，再做独立中间件回归。

空消息 0；Jetson Fast DDS 原始订阅返回 2,158 条，空消息 3，分别在新订阅

两个订阅各自的发现和接收时间不同，不能按序号一一指认哪条诊断空消息等于

序列化载荷长度与 CRC32 均一致。这是共同有效样本的校验，不是密码学逐字节
证明，也不是无丢帧证明。故障期间的真实数据缺失仍然存在。

## 避免测试自身隐藏问题

第一次 rclpy raw 回调实验在两端都报告空消息 0，但安装的 rclpy 3.3.21
执行器只在 `if msg` 为真时调用回调，`b''` 会被跳过。因此该实验不能证明
Jetson 接收层没有空消息。

改为诊断进程直接调用 subscription handle 的 `take_message(Image, True)`，
检查返回是否为 `None`，才捕获到成功返回的零长度载荷。没有修改现场安装的
rclpy，也没有让产品静默丢弃空消息。

同样，最初独立 C++ 测试使用 `take_next_sample` 时未复现；切换到 ROS
序列化订阅实际使用的 collection `DataReader::take` 后，旧库稳定复现
一帧有效数据后多出一条空消息。不能用不同读取接口的通过结果替代实际路径。

## 根因证据

独立短诊断进程加载追踪库；产品服务未加载该追踪库。

1. Fast DDS 向 TypeSupport 反序列化函数传入的 payload 已长为 0；函数返回
   成功，RMW 随后把它作为成功取得的序列化消息返回。
2. 对应 CacheChange 的 sequence=0、source timestamp=0、writer GUID 未知。
3. 同一指针的前一次缓存归还记录，原 sequence 为 393193，源时间为
   `1794485253944287912 ns`；调用栈为 `processGapMsg` →
   `History::remove_change_nts` → `RTPSReader::releaseCache` →
   `CacheChangePool::return_cache_to_pool`。
4. 相同缓存被回收清空后，非键值 DataReader 的 instance 仍引用它，随后
   collection take 再次访问。现场空消息已经在写盘之前产生。

安装版本：Fast DDS 2.6.11、rmw_fastrtps 6.2.10、rclpy 3.3.21、
rosbag2_transport 0.15.16。相机为 rmw_cyclonedds_cpp；本轮没有把现有
LooperHub checkout 当作已部署相机固件的源码身份凭据。

另有 22 秒 RTPS 元数据抓取，92,518 个数据报中未观察到无 DATA 标志的
DATA 子消息；未采集内核抓包丢弃统计，因此该观察不作穷尽性排除证据。

上游相同机制：[issue 6567](https://github.com/eProsima/Fast-DDS/issues/6567)，
[PR 6571](https://github.com/eProsima/Fast-DDS/pull/6571)。2026-11-12 核验时
PR 仍 open、未合并，当前 head `fd3fea7598099c5a93fe12c098413bdf403fe33f`。
本项目需独立验证 2.6.11 适配，不能把上游待合并方案称为官方已发布修复。

## 收窄修复与独立回归

最初尝试把未完成样本延后加入 instance，虽然消除了空消息，却在 KEEP_LAST
depth 1 的旧帧晚完成场景返回旧帧；该候选被拒绝，未部署到采集服务。

最终补丁只在 GAP 回收未完整样本前清除 DDS instance 的对应引用，保持
原先无回调的回收方式。内置发现 history 保持原路径；不改变 QoS、缓存
上限、分片组装时机、公共类布局或虚函数表。不加空消息过滤器。

独立协议回归使用 localhost、独立 domain 219 和合成话题，不访问相机：

| 场景 | 原库 2.6.11 | 修复库 |
| --- | --- | --- |
| 半帧被 GAP 取消后再收完整帧 | 多出 1 条空消息 | 仅 1 条有效消息 |
| 一个 DATA_FRAG 带齐所有分片 | 通过 | 通过 |
| 一帧缓存，旧帧晚完成 | 保留新帧 | 保留新帧 |
| 两帧按序分片 | 通过 | 通过 |
| 只有半帧和 GAP，无后续帧 | 返回空消息 | 无数据 |
| 连续 8 次半帧 / GAP，再收完整帧 | 返回多条空消息 | 仅 1 条有效消息 |
| 已完成帧遇到 GAP | 保留两帧 | 保留两帧 |

三个独立新建的真实左腕原始订阅，各观测约 12 秒，每个返回 363 条有效
载荷，共 1,089 条、空消息 0。每个进程的映射表均确认加载了修复库。
这是有界实测，不代表所有环境已完成验收。现有 175 项后端 / 系统回归通过。

本项目持有 Fast DDS 与 Asio 原始归档、许可证、哈希和补丁，构建此组件
不访问互联网或其他项目。运行库在项目内生成，入口为后端及继承环境的 ROS
子进程选择这一份库，不替换系统 ROS 安装。缺失编译产物时报安装错误，不
增加录制准入门槛；客户镜像构建时生成库，设备启动不编译或下载。
