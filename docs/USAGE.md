# 使用手册

完整桌面操作使用 Jetson 本地 Qt；手机提供现场控制。电脑网页版和浏览器 kiosk 已移除。

## 启动与连接

后端已运行时执行 `./native_dashboard/run.sh`。需要启动后端时先执行 `./scripts/run_dashboard.sh`。Qt 默认连接本机 8765 端口，不依赖浏览器。

手机与 Jetson 连接可互通的网络，打开 `http://<Jetson-IP>:8765/mobile`。手机断线、锁屏或退出 Qt，不会自动停止录制。

## 一次完整采集

1. 在 Qt 任务页或手机底部管理区选择/创建任务并进入。
2. 查看图像、VIO、存储和设备校时状态。仅有设备名或服务在线不足以证明输入正常。
3. 开始录制；需要记录完整校准过程时，可以随后点击开始校准。
4. 观察三路建图/定位状态；标定板是离线测量参考，不是自然场景校准的必要输入。
5. 停止并等待保存完成。EgoHalo 与 Jetson 分别保存，可以继续采下一条。
6. 采集结束后，在 Qt 录制库或手机底部执行手动回传合包。原始两端数据保留。
7. 用 Qt 检查完整性、评分和回放，必要时做优化。回放首次点击“准备并回放”时生成缓存，合包后不会自动生成。

手机管理区支持创建任务并填写操作说明、切换/结束任务和手动合包。录制/保存期间不修改任务；完整话题选择、回放和评分由 Qt 提供。

JPEG 编码仅使用 Jetson NVJPEG，准备回放仅使用硬件 H.264 编码；硬件不可用时报告对应功能错误。原始图像通过 WebRTC 或 Native 预览时，不再维护备用 JPEG；源 JPEG 输入直接复用已有压缩数据。

## 设备与配置

使用 `scripts/select_device.sh jetson-nx` 或 `jetson-nx-egohalo`，会同步配置与服务。切换前结束采集，切换后重新校准。配置模板保存在 `config/devices/`，现场配置修改需要按设备持久保存到模板。

## 离线轨迹优化

在 Qt 的 Optimize 页选择已合包的录制、包内相机和图像流，点击 Run。输入列表来自录制，不受当前连接设备配置影响；H.264 使用硬件解码，原始图像与 JPEG/PNG 使用各自的解码方式。内外参取自同一包的 CameraInfo 和 TF，将 VIO 换算到所选相机光心后，以最高 5 Hz 图像运行 COLMAP，并用 Sim3 对齐轨迹。完成后自动显示对比，也可从结果列表加载；原始 MCAP 保持不变。

Optimize 是离线重建与轨迹对比，不改变在线建图或三路校准。缺少相机参数、解码失败或重建失败时显示实际错误。

## 排查

- Qt 启动提示缺少运行库：安装对应发布包；开发机显式执行 `native_dashboard/build.sh`。
- 手机无法连接：核对 Jetson IP、同网连接和 `/healthz`。页面不要求互联网。
- 图像或 VIO 缺失：核对 USB/网络和 `/api/cameras` 输入年龄，再检查建图状态；不要只凭 ping 或容器存活调整算法。
- 录制不能开始：读取手机/Qt 给出的具体原因，先检查任务、话题、存储和校时。不要隐藏预检错误。
- 备用存储提示：检查实际采集盘挂载与 `.env` 中的来源标识。
- 图像连续但定位异常：分别检查原始 VIO、地图匹配和全局纠偏；完整性检查不能替代相对定位精度评估。

升级说明见 [部署文档](DEPLOYMENT.md)。通过 Qt 或手机页面操作任务和录制，两端状态同步更新。
