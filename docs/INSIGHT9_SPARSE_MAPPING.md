# Insight9 / EgoHalo 与 Insight3 共享地图定位

当前 Insight9 三相机配置运行 LooperVIO 的持续地标、共视局部 BA、位姿图与几何定位核心。头部和两个腕部各自使用设备 VIO；SuperPoint / SuperGlue 提供视觉特征。原 LooperVIO 工作树只读，迁入来源和适配记录见 [ORIGIN.json](../native_mapping/third_party/loopervio/ORIGIN.json)。

`jetson-nx-egohalo` 使用同一核心和适配器。设备 profile 的 `mapping` 指定头部双目图像、CameraInfo、VIO、IMU 与双目中心的物理坐标系及输出坐标系；Insight9 直接输入红外校正图，EgoHalo 经原有跨域中继和鱼眼校正后输入前置双目图。两种设备只在输入和外参配置上不同，地图优化、匹配和三路同步共用实现。

EgoHalo 使用 CameraInfo 中带标定版本的校正坐标系查 TF；物理双目中心由 `center_left_frame` 和 `center_right_frame` 计算。TF 未到齐时等待；旧标定坐标系的迟到图像不参与当前几何。原始 CameraInfo/TF 不改写、不交换。切换设备仍需启用对应的中继和校正服务，且新算法的实机精度必须用对应硬件数据测量。

## 处理与坐标

1. 头部校正双目按源时间配对，以 CameraInfo 的 P、R 和设备 TF 构造几何，右目匹配经过亚像素和往返检查。
2. 关键帧按时间采样，目标 2 Hz，静止时也持续建立地图。地标保留特征身份，由共视观测进行局部 BA。
3. 主定位使用至少三个关键帧观测且通过多帧重投影检查的地标。头部持续关联共享地图中的可见点并优化当前位姿。
4. 腕部通过检索、匹配、RANSAC 和鲁棒位姿优化定位。通过几何检查即更新地图到各自 VIO 的修正；相邻更新之间使用原始 VIO 运动。
5. 回环验证实际相机位置与旋转的一致性，更新位姿图后融合通过重投影检查的地标。已接受的腕部观测保存地标身份；普通 BA 和回环更新后，使用这些地标的刚体变形更新腕部位姿，不重复检索旧图像。头部与两腕修正作为同一地图版本一次提交，再生成展示点云。

对每台设备，`C = T_map_imu @ inverse(T_odom_imu)`，发布位姿为 `C @ T_odom_imu @ T_imu_center`。三台设备分别维护自己的 VIO 坐标，不作为刚性相机架处理。公共世界坐标系为 `insight9_map`，输出的是双目中心，目标 30 Hz。

三路在共同的 30 Hz 时间网格上插值，使用同一地图版本发布；Pose 与 TF 的时间戳相同。时钟偏移取启动后 100 个 VIO 样本的最小接收时间差，预热后固定；这是包含单向传输延迟的软件估计，不是硬件同步。状态记录 `source_clock_offset_ns`、`clock_ready` 和 `map_revision`；离线查找原始设备时间时，用输出时间减去该设备偏移。任一路未定位、时钟未就绪、VIO 失效、插值缺样或地图版本不一致时，不发布不完整的三路批次。

头部 RGB 光心与双目中心不同。若用 RGB 图像测板，评估必须通过其独立 TF 外参换算；使用红外图像测板时也应换算到所发布的双目中心。相机间相对平移偏差与公共板中心一致性偏差是不同指标，应分别标注。

## 服务与手机

- `insight9-sparse-mapper`：单一 C++ 地图所有者，串行执行地图写入、BA、回环和视觉查询。
- `insight3-global-localizer`：三路 ROS 输入适配、VIO 时间插值、位姿与状态发布。
- `superglue-inference`：既有 SuperPoint / SuperGlue 推理服务。

适配器直接订阅相机的校正图像；Dashboard 不再向旧 `/insight_mapping/...` 话题重复中继腕部图像。

三路位姿和状态保留原有话题：`/insight9_sparse_map/{pose,status}`、`/insight_global/insight3_a/{pose,status}`、`/insight_global/insight3_b/{pose,status}`。保留地标描述子云及标定参考图/点话题。状态含算法名、定位支持、会话 ID、重置时间和最后建图源时间，便于完整录制后离线复核。

手机使用 `/mobile`，继续通过 `/api/mobile/start`、`/api/mobile/stop` 录制，通过 `/api/mapping/reset` 开启新建图会话。只调用 `/insight_global/reset` 一次，等待服务完成再返回；清除三路定位与旧观测。录制可以先于校准开始，原始图像、VIO、CameraInfo、TF、地图位姿和状态一并保存。

手机会在缺少新视觉匹配时显示“VIO 推算”，便于操作者调整视角。匹配失败立即更新此状态，保留有效 VIO 的离板推算；跟踪丢失则清除修正并增加设备跟踪代次，拒绝旧代次的迟到结果。处理异常会停止输出，需重新校准，不切换备用算法。

VIO 超过两秒没有新数据时，状态不再报告已定位；断流恢复或 ROS 接收时钟跳变后，旧修正失效，重新建立时钟映射并获取视觉定位，不能直接复用断流前的坐标修正。

腕部底部遮罩只读取 `config/runtime.json` 中的 `localization.gripper_mask_height_ratio`，取值为 `[0, 1)`；缺少配置或值无效时直接报错。设置页保存后从下一次腕部特征处理生效，状态中的同名字段记录实际应用的比例。各设备 profile 使用相同的配置结构。

## 构建和验证

构建命令、依赖和真实核心的几何检查见 [native_mapping/README.md](../native_mapping/README.md)。只重建并切换两项定位服务，摄像头接收和采集 Dashboard 独立运行。

同包对照使用相同图像、原始 VIO、内外参和特征，从空地图按录制接收顺序重建，调用各版本实际的位姿发布逻辑。新版在统一采样时刻使用当时已有的三路修正，再按记录的时钟偏移换回图像源时间进行评估。独立板观测只用于误差计算，不作为地图约束，不进行误差驱动的裁切、尺度拟合或位姿对齐。

对照比较两版共同有效观测的相对位置 RMSE 和旋转误差；各版完整有效观测及定位覆盖另存。回放的核心几何结果与实际推理耗时、ROS 发布频率、录制完整性分别检查。保存源文件、执行文件、输入清单和逐点结果的指纹，以便复算。
