# Insight9 手机采集

手机与 Jetson 连接同一个 Wi-Fi，在浏览器打开 `http://<Jetson 地址>:8765/mobile`。
当前现场地址为 `http://192.168.19.222:8765/mobile`；DHCP 地址变化后以 Jetson 实际地址为准。
无需安装手机 App，也不需要公网连接。

## 操作

1. 确认头部 Insight9、右手 Insight3 A、左手 Insight3 B 的图像和 VIO 正常，查看存储位置和剩余空间。
2. 需要三路统一坐标时，点击“开始校准”，缓慢移动头部观察环境，让双手相机看到已建图区域。查看头部建图、右手定位、左手定位，等待“三路全局定位就绪”。“VIO 推算”表示当前未匹配地图，不算三路就绪。这里是重新建图和全局定位，不是重新估计相机内外参，也不是精度验收。
3. 点击“开始采集”，等待状态变为“采集中”。手机入口不要求激活语音任务；仅采原始数据时不要求地图或全局定位成功。
4. 需要看画面时点击“开启预览”，选择一台相机。预览只使用现有 WebRTC/H.264 通道，请使用支持 H.264 WebRTC 的手机浏览器；没有图片回退。视频异常会提示重新开启，录制不受预览失败影响。
5. 点击“停止并保存”，等待“保存完成”后再关闭设备。失败时保留并显示后端错误，不把停止请求受理当作保存成功。

“开始校准”复用现有建图重置接口，会清空当前地图和定位。三台相机图像/VIO 不全时禁用；启动、录制、保存期间也禁用。后端在录制和保存时拒绝地图重置。

手机断网、锁屏或关闭页面不会停止录制；重新打开页面可以继续查看并停止当前手机录制。
网页在后台时关闭该页的视频连接，回到前台时重新建立同一种 WebRTC 连接。
页面只允许停止手机入口启动的录制；桌面开始的录制仍由桌面停止。

## 数据与边界

建图轨迹的标定板精度测试使用独立离线工具，板制作、外参要求、采集时间线与指标见 [标定板参照精度测试](BOARD_ACCURACY_PROTOCOL.md)。手机仍只负责校准和采集启停。

- 复用 Insight Dashboard 的唯一录制管理器，桌面与手机不能同时启动第二个录制器。
- 录制状态与建图状态独立轮询；建图接口失败或卡住不会禁用录制的停止按钮。
- 手机停止请求在录制器持锁时核验路径和录制模式；受理请求后切换到另一条录制，旧请求会被拒绝执行。
- 数据写入当前录制根目录下的 `insight9_mobile/insight9_<时间>_<编号>/`，不改现有任务和目录选择。
- 使用当前配置的默认录制话题，包含图像、原始 VIO、IMU、标定信息和可用的全局 Pose。页面明确显示备用存储；它不会自动切换采集盘。
- Jetson NX 默认录制为 32 个话题，增加头部左右目校正图和 CameraInfo、三路 VIO 状态、
  地图特征/状态/关键帧与两腕定位状态。暂停后恢复录制时重发按 child frame 汇总的完整
  静态 TF，避免只保存最后一个设备的外参。按当前实测 20 Hz，头部双目约增加 14 MB/s 原始图像数据；
  重建图和复测步骤见 [重建图前优化与数据规范](MAPPING_REBUILD_VALIDATION.md)。
- 接口为 `GET /api/mobile/status`、`POST /api/mobile/start`、`POST /api/mobile/stop`。命令携带唯一 `command_id`，停止还需携带状态接口返回的 `output_path`，防止旧页面停止新的一条。
- 不导入或调用 Ego 系统。启用分布式录制或者不是 Insight9 + 双 Insight3 配置时，此入口明确拒绝启动。
- 手机和桌面共用 `web_dashboard/src/shared/webrtc.js` 中的一份信令处理，显示和连接生命周期留在各自页面；手机不增加图片回退。手机命令编号统一使用 `crypto.getRandomValues`，不再提供另一种生成方式。
- 手机页面使用预检已经读到的剩余容量，不重复查询磁盘。校准接口必须具有录制管理器，依赖缺失时不会跳过录制保护。
- 本次部署使用现有局域网，没有切换 Wi-Fi、激活热点或修改相机 USB 网络。

## 验证记录（2026-10-27）

- 代码精简与问题修复：4 项原子停止/必需依赖检查、11 项手机采集检查、12 项既有录制/建图检查通过；共用信令验证 offer/ICE 顺序、失败仅通知一次和过期回调隔离。浏览器模拟建图 500、建图延迟、采集接口失败，以及局域网 HTTP 下的唯一编号生成，均按预期响应。此轮未新建现场录制或重置现场地图。
- 相机数据离线期间，用独立生成的 H.264 视频流验证共用信令：手机与桌面相机模块均实际解码 320×240 画面、各显示 17 帧，无 JavaScript 异常；它验证浏览器接线，不代表现场相机质量或端到端延迟验收。
- 手机校准扩展：2 项后端检查和 3 项既有建图接口检查通过；模拟页面验证请求成功/失败、繁忙锁定、缺相机、VIO 推算/离线、原始采集与多宽度布局。校准请求均使用模拟响应，没有重置现场地图。证据在 `~/workspaces/insight_capture_tests/mobile_calibration_20261027/`。
- 11 项手机接口、并发、重复请求、旧停止命令、Ego 隔离、断线收尾、预检及空闲停止检查通过；12 项已有录制存储、标定录制和建图接口检查通过。
- 手机尺寸 Chromium 实际点击启停，关闭并重新打开页面后录制仍在继续；320、390、768 像素宽度无横向溢出，页面无 JavaScript 异常。
- 一条实际 MCAP 为 5.818 秒、19 个话题、10,749 条消息；三路图像各 175 帧，深度检查图像和 IMU 均无缺失。Insight3 A VIO 被检查器报告缺失 3 条（0.52%），因此这条不能记作全部质量检查通过。
- 支持 H.264 的 Chromium 实测三路 WebRTC 视频均连续解码：约 6 秒分别显示头部 83 帧、右手 88 帧、左手 89 帧。开发镜像附带的 Playwright Chromium 不支持 H.264，不能用于视频解码验收；没有为此增加图片回退。
- 随后用户调整硬件、头部相机从 USB 列表消失，页面正确禁止新起录。用户要求先完成部署，因此未继续做预览与录制同时运行的额外录制。
- 现有任务测试中有一项未通过：断言要求“不能切换任务”，现有接口返回“不能修改任务”。本次没有修改任务接口。
