# 三相机手机采集

手机与 Jetson 连接同一个 Wi-Fi，在浏览器打开 `http://<Jetson 地址>:8765/mobile`。

EgoHalo 配置默认录制八路原始图像：头部四路 H.264，以及两腕各自的 infra1/infra2 NV12 图像。建图校正图像和标定参考图不写入录制包；内参、外参、原始 VIO、统一位姿和定位状态仍保存。八路均参与合包时的共同区间与缺帧检查。H.264 是编码格式，不代表各路同时曝光或不会丢帧。
当前现场地址为 `http://192.168.19.222:8765/mobile`；DHCP 地址变化后以 Jetson 实际地址为准。
无需安装 App。页面从当前配置读取设备、头部类型和预览视角，支持 Insight9 或 EgoHalo 与两台 Insight3。

## 完整校准录制

1. 在“任务管理”选择数采任务，确认三台设备的图像、原始 VIO、相机参数、存储和时钟检查通过。
2. 点击“开始采集”，等待“采集中”。此时不要求已经建图或全局定位成功。
3. 点击“开始校准”，让头部观察环境、两台腕部看到共同区域，等待“三路全局定位就绪”。
   这会清空当前地图并重新定位，不会重新估计相机内外参。
4. 继续录制静止、运动、离板及回板过程；用于误差评估的标定板全程固定。
5. 点击“停止并保存”，等待“保存完成”。EgoHalo 需要两端保存、头部数据回传和合并完成后才显示保存成功。

完整过程记录原始输入、校准前后状态和可用的全局位姿。地图状态中的会话编号、`generation`
和 `last_reset_wall_ns` 给出重置边界；离线精度统计从校准完成后开始。标定板只作为离线测量参照，
不向在线算法提供标签布局或尺寸，方法见 [标定板参照精度测试](BOARD_ACCURACY_PROTOCOL.md)。

普通采集模式允许录制中校准；起录、停止、保存期间，以及原始 VIO 标定专用录制期间禁止重置。
图像或原始 VIO 不全时也不能校准。定位和原始录制状态独立显示，“VIO 推算”不算当前地图匹配就绪。

## 共用录制与数据

- 手机复用普通录制的预检、任务编号、起停和保存流程，没有独立的手机录制模式或备用录制器。
  手机和桌面操作同一条普通采集；停止请求在录制器持锁时核验路径，旧请求不会停止新的一条。
- 校准前起录仅取消对全局位姿就绪的要求，仍要求原始图像、VIO、相机参数、必要话题和存储正常。
  EgoHalo 仍执行现有双端预检、NTP 及两两时钟偏差门槛，缺失输入和时钟失败均不能起录。
- EgoHalo 使用现有双端协调器：头部原始四路 H.264、VIO、IMU、内参与工厂外参由头部 TF 卡保存；
  Jetson 记录两腕双目、VIO、IMU、三路统一位姿、头部校正输入及建图诊断，然后校验取回并合并。
- 数据写入当前任务目录，完整原始参与者目录和合并包均保留。校准前尚无发布内容的派生话题会在产生后进入同一条录制。
  静态 TF 在正式写入时按 child frame 汇总重发，包含设备和校正视角的外参。
- 页面明确显示当前存储和备用存储状态。没有改变设备配置选择、存储选择或自动重建失败数据的行为。
- 状态接口为 `GET /api/mobile/status`；起停为 `POST /api/mobile/start`、`POST /api/mobile/stop`。
  命令携带唯一 `command_id`，停止还必须携带状态返回的 `output_path`。重复命令不会重复起录。

## 断线与预览

手机断网、锁屏或关闭页面不会停止录制；重新打开后可以查看并停止当前采集。保存期间显示实际双端合并状态，
不会因为停止命令已受理就提前显示“保存完成”。建图接口失败也不会禁用录制停止按钮。

点击“开启预览”后选择配置中的视角；EgoHalo 提供四路头部视角及两路腕部视角。一次只开一路，
复用现有 WebRTC/H.264 通道和信令。浏览器须支持 H.264 WebRTC；视频异常直接提示，不增加图片回退。
切入后台时关闭该页面的视频连接，回到前台时重新建立同一种连接。
