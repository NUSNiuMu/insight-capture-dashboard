# 叠杯批量数据采集标准作业规范

## 1. 目的与适用范围

本规范用于三相机系统的叠杯示教批量采集。目标不是只完成动作，而是保证每个 episode
都有一致的任务定义、可用的三相机全局位姿、完整的数据流和可追溯的验收结果。

参考教学视频包含 **3-3-3、3-6-3、6-6、1-10-1、Cycle** 五种动作。第一批采集必须
先在任务单中选定一种，不得把不同动作混在同一个任务标签里。建议先用 3-3-3 跑通
30 条试采和阈值验证，再扩展到其他动作。

- 教学参考：[Bilibili 叠杯慢动作分解](https://www.bilibili.com/video/BV1Dp4y1x79W/)
- 规则术语参考：[WSSA Sport Stacking Rule Book](https://www.thewssa.com/docs/rules_rules.pdf)

本文规定的是机器人学习数采边界，不要求采集员追求竞技计时成绩。

## 2. 必须理解的四个对象

- **episode / 采集单元**：一次录制只完成一次指定叠杯动作，从标准初态到标准终态。
- **批次**：同一采集员、同一任务类型、同一设备配置和同一场地连续完成的一组 episode。
- **检测位**：让左手、右手两台 Insight3 以机械方式重复落位的固定治具，不是靠人目测
  “放回大概位置”。每个夹爪相机至少应有明确止挡和方向约束。
- **检测位基准**：已确认校准正确时保存的两台 Insight3 检测位 Pose，以及当时冻结的
  Insight9 自然特征地图。头戴 Insight9 不要求回到固定位置，而是通过重新观察已建图区域
  检查相对冻结地图的闭环误差。普通采集员不得为消除告警而覆盖基准。

## 3. 人员权限

| 操作 | 采集员 | 组长/标定负责人 |
| --- | --- | --- |
| 开始、停止录制 | 可以 | 可以 |
| 每单元检测 | 必须 | 必须 |
| 重新放置后复检 | 可以 | 可以 |
| 开始重新校准 | 告警后可以 | 可以 |
| 设置/覆盖检测位基准 | 不可以 | 可以，且须确认校准正确 |
| 放行隔离数据 | 不可以 | 可以，须有复核记录 |

## 4. 场地与物料标准

1. 相机、USB 声卡、麦克风、音响和线缆固定，线缆不能牵拉相机；镜片清洁且无遮挡。
2. 检测治具、桌面、杯子初始位置使用不可移动标记；治具不得放在软垫或可变形表面。
3. 三路相机视野必须覆盖任务关键区，手和杯子在关键动作中不得长期出画或被衣袖遮挡。
4. 灯具、窗帘和桌面反光条件在一个批次内保持不变；出现频闪、严重过曝或红外画面失真时
   停止采集。
5. 每个任务使用同型号、同数量的杯子。损坏、变形、明显污渍或摩擦状态异常的杯子立即
   替换，并在批次记录中登记。
6. 麦克风只作为控制入口。音响与麦克风保持足够距离，播报期间不要同时下口令。

## 5. 任务卡与命名

每个批次开始前填写：

- `task_id`：`cup_stack_3_3_3`、`cup_stack_3_6_3`、`cup_stack_6_6`、
  `cup_stack_1_10_1` 或 `cup_stack_cycle`；
- 采集员 ID、批次 ID、日期、杯子组 ID、设备 profile；
- 规定的起手方向、叠放顺序、允许速度范围和成功终态；
- 本批计划的速度、起始位置或动作风格变化矩阵；变化必须是预先定义的，不能临场随意改变；
- 生成的 rosbag 名称、执行结果、检测位结果和重录关联。

语音录制生成 `looper_record_时间戳`。采集表以系统返回的 rosbag 名称为主键，不得只用
“第几个动作”口头对应。需要重录时保留原记录并标记 `technical_invalid`，新条目填写
`retry_of=<原 bag>`。

## 6. 每日开班准备

1. 开机后等待三路相机和建图服务在线；确认 `/3d` 三个画面持续更新，无 stale/offline。
2. 播放音响测试并做一次麦克风转写测试；采集员在实际站位说口令，不能只在设备旁测试。
3. 说“开始校准”。按现场规定移动 Insight9 建立工作区地图，并让两路 Insight3 都看见
   已建图区域，直到听到“校准完成”。
4. 将左右手两台 Insight3 放入检测治具，松手，避免线缆受力，至少静止 1.2 秒；头戴
   Insight9 正常佩戴即可。
5. 让 Insight9 扫视任务工作区，确认自然场景稀疏地图覆盖充足。组长说“设置检测位”，
   系统保存双手检测位 Pose，并冻结当前 Insight9 地图的关键帧上限。已有有效基准时不要覆盖。
6. 每次检查前用 Insight9 短暂扫视已建图区域；连续执行三次“检查相机”，三次都 PASS
   才开班。任一次不通过，按第 9 节处理。
7. 录制一条标准试采，执行数据完整性和轨迹评分，并人工查看三路画面后再开始批量采集。

出现以下任一情况必须重新执行开班准备：相机/治具被拆装或撞击、线缆重新布置、场地移动、
后端或定位服务异常重启、连续两次检测不稳定、检测结果要求重校准。

## 7. 单个 episode 标准流程

### 7.1 动作前

1. 按任务卡摆好杯子；数量、朝向、三组间距和桌面标记必须一致。
2. 穿戴或拿起相机后确认线缆自由，不得在动作中拉到极限。
3. 双手和头部进入标准初始姿态，保持约 1 秒。
4. 说“开始录制”；听到“录制已经开始”后再动作，不能把播报当作动作起点的一部分。

### 7.2 动作中

1. 只执行任务卡指定的一种动作，一次录制不得连续做多个完整 cycle。
2. 动作顺序、左右手规则、初态和终态必须符合任务卡；杯子倒下、滚出工作区或漏叠均视为
   `task_failure`。
3. 正常的速度和轨迹差异可以保留；故意停顿、摆拍、手离开任务区或接受旁人协助不合格。
4. 若任务目标包含失败恢复，可保留真实失误并标记具体失败类型；否则动作失败不得冒充成功样本。

### 7.3 动作后

1. 到达标准终态后保持约 1 秒，再说“停止录制”。
2. 听到提示后，将左右手 Insight3 完全放入治具，松手并静止至少 1.2 秒；同时用头戴
   Insight9 短暂扫视已建图工作区，不要求回到固定头部位置。
3. 说“检查相机”，听到“开始检测”后等待结果。只有听到“双手相机位置和头部相机地图
   闭环正常”或页面显示 PASS，才能整理下一条数据。
4. 将 rosbag 名称、动作成功/失败、检测结果和异常备注写入采集表。

## 8. 自动检测的判定口径

系统对左右手检测位 Pose 取至少 0.8 秒稳定窗口，并要求 Insight9 为当前 episode 产生一条
相对批次冻结地图的新闭环，具体检查：

- Insight9 建图在线，两路 Insight3 在本轮地图中已经完成全局定位；全局定位成功后允许
  `vio_only` 连续跟踪，不强制检测瞬间再次命中地图；
- 地图确认点不少于 30；
- 两路 Insight3 pose 新鲜、样本数量足够且满足静止阈值；
- Insight3 A、Insight3 B 的全局位置和方向与保存的检测位一致；
- Insight9 当前画面对冻结关键帧范围内的自然特征完成 SuperPoint/SuperGlue 匹配、PnP 和
  多帧共识；本次闭环序号必须晚于上一条 PASS，且结果年龄不超过 5 秒，不能重复使用 episode
  中更早的旧结果；
- Insight9 闭环测得的 `map_to_odom` 与当前 VIO 累积结果之间的平移、旋转校正量在阈值内；
- mapper 进程、地图 session 或冻结 reference 发生变化时，原检测位基准立即失效。

默认阈值：

| 相机/方法 | 静止窗口上限 | PASS | RETRY | RECALIBRATE |
| --- | --- | --- | --- | --- |
| Insight3 A/B | 6 mm、1.5° | ≤ 10 mm、≤ 2° | ≤ 25 mm、≤ 5° | > 25 mm 或 > 5° |
| Insight9 冻结地图闭环 | 不要求固定 Pose | ≤ 40 mm、≤ 8° | 无新闭环，或 ≤ 80 mm、≤ 15° | > 80 mm 或 > 15° |

任一检查项达到更高等级，整体结果就采用更高等级；结果会直接列出超限相机。Insight3 是
操作端，阈值更严格；Insight9 使用任意头部 Pose 下的闭环创新量，不再比较固定检测位 Pose。

这些是首版工程阈值，不是相机厂商精度承诺。正式量产前必须对 Insight3 治具做至少 30 次
“取出—放回”重复性实验，并让 Insight9 在实际站位、视角和照明组合下做至少 30 次自然场景
闭环实验。通过阈值应高于正常误差的 99% 分位并保留任务精度余量；若治具或场景纹理无法稳定
达到阈值，应先改善现场条件，不能单纯放宽软件阈值。

## 9. 异常与数据隔离

### 9.1 提示未静止或条件未满足

检查左右手相机是否完全入位、手是否松开、线缆是否顶住治具；若提示没有新闭环，让 Insight9
换一个方向扫视已建图工作区后复检。不要立即重校准，也不要反复覆盖基准。场景没有足够稳定
自然特征时，本条只能标为 `unverified`，不能当作 PASS。

### 9.2 RETRY

重新取出并放回两台 Insight3，同时让 Insight9 再次扫视已建图区域后复检。高质量闭环连续
两次仍超出 RETRY 范围时按 RECALIBRATE 处理；只是自然特征不足时不得误判为漂移。

### 9.3 RECALIBRATE

1. 立即停止后续采集，把**本次 episode** 标记为 `technical_quarantine`；
2. 如果中间曾跳过单元检测，则从“上一次 PASS”之后的所有 episode 全部隔离；
3. 说“开始校准”，等待“校准完成”；
4. 两台 Insight3 放回检测位，Insight9 扫视重新建立的工作区地图；重新校准会改变地图 session，
   因此由组长重新设置本批检测基准；
5. PASS 后重新录制所有隔离 episode；未复核前不得进入正式训练集。

### 9.4 数据流或录包异常

出现 merge error、incomplete、相机 stale、明显丢帧、时间跳变或轨迹异常时，该 bag 标记为
`technical_invalid`。定位问题并完成一条试采验证后再恢复批量采集。

## 10. 数据验收

每条正式 episode 同时满足以下条件才算可交付：

- 任务 ID、采集员、批次、bag 名称和执行结果齐全；
- 起始和结束状态符合任务卡，动作关键阶段三路可见；
- 录包合并完成，无完整性 FAIL；
- 轨迹评分已生成且没有需人工处理的异常；
- 该 episode 结束后的检测位结果为 PASS；
- 不在 `technical_quarantine` 或 `technical_invalid` 状态；
- 重录关系和保留/剔除决策可追溯。

人工复核至少覆盖：每批前 3 条、之后每 10 条抽 1 条、所有 task failure、所有复检/重校准前后
的条目。批次结束后统一检查 bag 数、任务表行数、检测结果文件数和计划数量一致。

检测记录保存在 `outputs/results/capture_checks/`：`reference.json` 是当前基准，
`history.jsonl` 是完整历史，每个已关联 bag 另有同名 JSON 结果。

## 11. 语音引导设计

需要完整准备语音，但不应把整份 SOP 逐条播报。正确做法是“纸面/网页完整规范 + 关键节点短语音 +
页面同态显示”：

| 采集员口令 | 系统动作 | 关键回复 |
| --- | --- | --- |
| 开始录制/开始采集 | 新建一条默认 topic 录制 | 录制已经开始 |
| 停止录制/停止采集 | 排空单个 MCAP writer 并发布 | 提醒双手归位、头部扫视并检查相机 |
| 检查相机/开始检测 | 双手检测位 + Insight9 冻结地图新闭环 | PASS、重新放置/扫视或重新校准 |
| 开始校准/重新校准 | 清空当前地图和两路全局定位 | 校准已经开始；两路重新定位后播报校准完成 |
| 设置检测位 | 保存双手 Pose 并冻结 Insight9 地图 | 检测位基准已经记录，仅组长使用 |

这些确定性口令无需先说唤醒词，也不依赖外部推理。自然语言问答才使用“宸境”唤醒。系统回复
没有播完时不要讲话；没有听清回复时以 `/3d` 页面状态为准，不得凭猜测继续。

## 12. 班次结束

1. 最后一条 episode 完成检测并记录结果；等待录包 merge 完成。
2. 完成批次数量核对、完整性/评分检查和抽样回放。
3. 导出或备份采集表；把隔离和重录条目交给组长复核。
4. 相机放回保护位置，检查镜片、线缆和治具是否需要维护。
5. 记录本班重校准次数、复检次数、技术无效数和任务失败数，用于次日改进。
