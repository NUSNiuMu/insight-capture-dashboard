# Insight9 / Insight3 定位核心

从只读 LooperVIO 工作树迁入持续地标、共视局部 BA、关键帧裁减、回环和几何定位。来源版本、实际修改和文件指纹见 `third_party/loopervio/ORIGIN.json`。保留原版权声明；未编译的 VIO 实现不随迁入代码携带。

线上只有一条路径：SuperPoint/SuperGlue → 双目亚像素细化 → LooperVIO 地标与共视优化 → 腕部几何定位。设备自身 VIO 提供相邻视觉更新之间的运动。没有 ORB 备选路径，也不回用未经多帧验证的原始三维点。

## 几何与状态

- 关键帧固定按时间采样，目标 2 Hz，静止时也建图。腕部图像目标 4 Hz；特征提取与 C++ 求解通过各自有界的逐路最新帧队列重叠执行，过载时丢弃过时的推理输入。地图写入、局部 BA、回环与查询仍由同一个 C++ 请求线程执行，不并发改图，也不影响原始图像录制链路。
- 头部按共享地图中可见地标进行关联和位姿优化；回环在两个独立共视参考的相机位置与旋转一致时建立，修正后以真实重投影检查融合地标。
- 腕部定位保留接受的图像像素与成熟地标身份；每次局部 BA 或回环后，以更新后的三维点重新优化同一图像的位姿，不重复匹配、不把地图深度变化强行视为刚体变形。与图像定位共用稳健重投影求解器，地图更新至少 10 个内点、80% 内点比例、四个图像网格支持，单点重投影误差不超过 3 px，并检查按场景深度归一化的六维位姿信息矩阵特征值比例（至少 1e-6），拒绝几何退化。失败时清除该路输出并记录原因，等待新的图像定位；不继续发布无法验证的修正。每次地图事务返回同一 `map_revision` 的头部及两腕修正，ROS 层一次加锁提交后才传输地图点云。
- 主定位仅使用至少被三个关键帧观测、且通过多帧重投影检查的地标。保留各个 SuperPoint 特征身份，不按图像网格删除其他有效点。
- 腕部定位采用 RANSAC、1 px Huber 细化、3 px 几何剔除及再次拟合；至少 40 个内点、50% 内点比例、四个图像网格支持，并且同一图像对两个地图参考的相机位置解相差不超过 10 mm、旋转差不超过 1°，才接受图像定位。可靠性不依赖已经可能漂移的 VIO 来验证跨帧运动。
- 三路使用同一个六维误差状态 EKF 实现，保留完整位置/旋转协方差，在设备 VIO 运动上预测。头部的全局滤波修正统一作用于三路；两腕在头部 VIO 坐标系中融合相对定位，避免头部平滑进度改变头手相对位置。观测噪声默认标准差为位置 3 mm、旋转 0.3°，过程噪声为 10 mm/√s、0.5°/√s；这是工程噪声模型，未当作实测测量不确定度。更新幅度在当前物理双目中心计算，不比较依赖 VIO 原点的 `map_from_odom` 平移量。
- 位置创新不超过 5 cm 时执行 EKF 更新，后验以 50 ms 时间常数逐步注入共同 30 Hz 输出。优先分配腕部相对纠偏预算，其余用于三路共同修正，并按实际头手距离计入转动的杠杆效应；最终每路平移注入不超过 0.15 m/s，即每个 30 Hz 发布周期最多 5 mm。原始 VIO 运动不受此限制。超过 5 cm 仅在可靠几何定位通过后允许直接重定位：腕部须通过上述双参考验证；头部须有至少 40 个成熟地标支持的位姿优化或经共视验证的回环。未验证的大修正保留预测、明确标注等待重定位，不用 VIO 漂移一致性来拒绝正确的大视觉修正。
- 地图修订只替换同一旧图像约束对 EKF 后验的贡献，按原卡尔曼增益及后续运动传播其影响，不重复作为独立测量增加置信度；同时核验图像源标识。小地图修正同样逐步注入，大的地图修正须等待可靠图像定位。没有新头部几何观测时只预测，不将 VIO 推算重新当作测量融合。校准重置及 VIO 跟踪/时钟失效会清空滤波状态，没有第二套定位路径。
- 三台设备分别保留自己的 VIO 坐标，不能作为刚性三相机架处理。原始观测为 `C = map_from_imu @ inverse(odom_from_imu)`；腕部相对观测为 `inverse(head_raw_C) @ wrist_raw_C`。输出头部中心为 `head_filtered_C @ head_odom_from_imu @ head_imu_from_center`，腕部中心为 `head_filtered_C @ wrist_relative_filtered_C @ wrist_odom_from_imu @ wrist_imu_from_center`，两个腕部的相对位置仍可独立变化。
- 使用 CameraInfo 的校正投影矩阵与 TF 外参，头部右目由校正基线构造。RGB 评估通过其独立外参换算，不能把 RGB 光心当成双目中心。

ROS 层发布原有三路位姿、状态、地标描述子云与标定参考图，保留手机的开始校准和录制接口。三路在共同的 30 Hz 网格采样，Pose 与 TF 使用同一时间戳；软件时钟偏移估计和地图版本随状态记录。没有新视觉匹配时，状态明确标识运动由 VIO 推算。

## 构建与验证

```bash
docker build --network host -f native_mapping/Dockerfile.dependencies -t insight-loopervio-deps:2.1 native_mapping
docker compose build insight9-sparse-mapper
docker compose up -d --no-deps insight9-sparse-mapper insight3-global-localizer
```

`insight9-sparse-mapper` 运行唯一 C++ 核心，`insight3-global-localizer` 运行三路 ROS 适配层。重建、重置与传输故障均使用这条路径。

在装有构建依赖的镜像内运行真实几何检查：

```bash
PYTHONPATH=. python3 native_mapping/tests/check_geometry.py /usr/local/bin/insight_mapping
```

检查已知空间点的双目建图、BA、两路腕部位姿、错误对应拒绝、普通局部地图更新时的两腕修正、点云传输，以及重置后重新建图。另可构建并运行 `check_pose_graph` 目标，检查非零、非单位旋转的世界原点在位姿图中保持固定，防止未初始化的稳定参考位姿破坏回环约束，并检查腕部参考关键帧在使用期间不会被延迟删除、释放后可裁减。

同包对照在独立进程运行冻结的旧版与新版，使用相同图像、原始 VIO、内参、外参和时间顺序。标定板只用于独立误差计算，不参与建图或拟合算法参数；全部精度统计从录制中的校准完成时刻开始，后续跟踪失败和纠偏尖峰均保留。两版按共同有效观测比较 RMSE、P95、最大值并另报覆盖率。每个原始 VIO 消息收到时选取当时已存在的修正，构造 30 Hz 双目中心位姿，再按图像源时间插值得到评估位姿，避免把图像接收时间误当作源时间。评估同时给出共同标定板中心偏差和相机间相对平移偏差。几何回放与实际运行耗时分开记录。复核脚本、输入清单、版本指纹和逐点结果归档于本次测试目录。
